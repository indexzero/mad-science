guest.wasm

jco-worker-csp shows that JavaScript generated from a WebAssembly component can run in a Web Worker whose CSP allows it, on a page whose CSP refuses it.

This page: the bytes of guest.wasm, the WIT read back from those bytes, and the glue that jco generates from them.

guest.wasm is one WebAssembly component: a binary whose preamble is 00 61 73 6D · version 0d 00 · layer 01 00 (a core module's layer is 00 00). Its interface types are part of the binary. componentEmbed, jco-transpile's build of wasm-tools component embed, encodes the WIT world guest into a component-type custom section of the core module. componentNew (wasm-tools component new) then reads that section and wraps the core module in component-level type, import and export definitions, joined to the core functions by canon lift / canon lower (the Canonical ABI). The page recovers the WIT from the bytes alone with componentWit (wasm-tools component wit), so no .wit file ships. The recovered world is named root in package root:component: the name guest does not come back. The signature of log is in the component's type section, in the print lines in the next box.
